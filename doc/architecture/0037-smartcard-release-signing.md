# ADR 0037: Smart-card release signing and artifact naming

Status: Accepted

Date: 2026-08-22

## Context

Release distributions require cryptographic authenticity. Traditional Android
signing workflows rely on file-based Java KeyStore (\`.jks\` / \`.keystore\`) files
persisted on developer workstations or in CI secrets. For an identity and
security product, storing release private keys on disk introduces unnecessary
credential exposure risks.

Finnish identity cards (FINEID) contain hardware-isolated private keys for
authentication (PIN 1) and qualified electronic signatures (PIN 2, NIST P-384 /
ECDSA). Physical cards enforce on-token signing and short-lived in-memory PIN
collection. Furthermore, Google Play App Signing allows separating the developer
Upload Key from the permanent App Signing Key held in cloud HSMs, enabling
hardware keys to serve as release credentials without update discontinuity when
physical cards reach their 5-year expiration cycle.

## Decision

1. **Hardware-Bound Release Signing**:
   When file-based \`keystore.properties\` is absent, release artifacts are signed
   directly using the developer's identity card PIN 2 (qualified signature) key
   through the local PKCS#11 bridge (\`/usr/local/lib/librefineid_pkcs11_sign.dylib\`)
   and JDK's \`SunPKCS11\` provider.

2. **Native Certificate Export**:
   On macOS, public certificate material is inspected and exported directly from
   CryptoTokenKit using the system \`security export-smartcard token\` command or
   Security framework bindings, eliminating external middleware dependencies.
   Exported certificate material is saved to \`certificates-from-smart-card/\`
   which is explicitly ignored in \`.gitignore\`.

3. **Deterministic Release Naming**:
   \`Scripts/build-release-apk.sh\` derives the canonical package name from the
   stamped release pair in \`version.properties\`:
   \`refineid-\${versionName}.\${buildNumber}.apk\` (e.g. \`refineid-26.8.22.1650.apk\`).

4. **Automated Verification**:
   The script invokes \`apksigner sign\` with JVM module exports for
   \`jdk.crypto.cryptoki/sun.security.pkcs11\` and immediately validates the
   resulting package using \`apksigner verify\`.

## Consequences

- No release private keys ever exist on disk or in repository artifacts.
- Cutting a production release requires physical possession of the identity card
  and interactive PIN 2 entry.
- Direct website distribution packages carry valid APK Signature Scheme v3
  signatures generated by the hardware token.
- Google Play App Bundles (AAB) can be signed with the same hardware upload key
  prior to Play Store upload.
